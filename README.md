# DotaCodex — учебный MVP

DotaCodex — прототип русскоязычной вики по Dota 2. Дизайн и расположение разделов основаны на приложенных Figma-макетах: главная, каталог героев, карточка героя, предметы, патчи, гайд и конструктор гайдов.

> **Важно:** записи о героях, предметах, патчах и гайды в seed-наборе демонстрационные. Это учебные данные для демонстрации структуры приложения, а не проверенная актуальная игровая база. Авторизация и отправка e-mail пока не реализованы.

## Стек

- **Node.js 22.13+** — HTTP-сервер и REST API.
- **Supabase PostgreSQL** — облачная реляционная база, к которой сервер подключается через `pg`.
- **Tailwind CSS 4** — сборка стилей локальным CLI.
- HTML, CSS и JavaScript — интерактивный адаптивный интерфейс.
- `node:test` — автоматические тесты.
- GitHub Actions — автоматический запуск тестов при `push` и `pull_request`.
- Docker и GitHub Container Registry (GHCR) — контейнеризация приложения и публикация образа из `main` после успешных тестов.

## Запуск

1. Установи Node.js версии 22.13 или новее.
2. Создай проект в Supabase и скопируй URI подключения из кнопки **Connect** в панели проекта. Если прямое подключение недоступно в твоей сети, выбери **Session pooler**. Если в пароле есть символы вроде `@`, `#` или пробелов, закодируй их для URI.
3. Скопируй `.env.example` в `.env` и вставь URI в `DATABASE_URL`. Пароль базы не публикуй и не добавляй в браузерный код.
4. Установи зависимости и создай таблицы с демонстрационными данными:

   ```bash
   npm install
   npm run db:setup
   ```

5. Запусти приложение:

   ```bash
   npm start
   ```

6. Открой <http://127.0.0.1:8000>.

Для режима разработки с перезапуском сервера при изменениях:

```bash
npm run dev
```

Для автоматических тестов:

```bash
npm test
```

## Docker

Соберите образ и запустите контейнер из корня проекта:

```bash
docker build -t dotacodex .
docker run --name dotacodex --env-file .env -p 8000:8000 -d dotacodex
```

Откройте <http://localhost:8000>. Состояние контейнера можно проверить командой `docker ps`, а остановить — `docker stop dotacodex`.

## GitHub Actions и публикация образа

Workflow в `.github/workflows/ci.yml` проверяет синтаксис JavaScript и запускает `npm test` на `push` и `pull_request`. После успешных проверок отдельная задача собирает и публикует образ только при `push` в `main`. Для входа в GHCR используется автоматически предоставляемый `GITHUB_TOKEN`; в настройках репозитория для Actions должно быть разрешено создание и запись пакетов (Settings → Actions → General → Workflow permissions).

Образ публикуется с тегами `latest` и коротким SHA коммита по адресу `ghcr.io/<владелец>/<репозиторий>`. Загрузить его можно так:

```bash
docker pull ghcr.io/<владелец>/<репозиторий>:latest
```

Чтобы дать доступ к образу без авторизации, сделайте package публичным в разделе Packages репозитория; новый package в GHCR обычно создаётся приватным.

Для повторной сборки Tailwind CSS при разработке открой второй терминал и запусти `npm run watch:css`. SQL-скрипты схемы и демонстрационных данных находятся в `db/schema.sql` и `db/seed.sql`; их также можно выполнить в Supabase SQL Editor.

Workflow GitHub Actions использует секрет `SUPABASE_DATABASE_URL`. Добавь его в **Settings → Secrets and variables → Actions** перед запуском CI.

Проверка API и соединения с Supabase: <http://127.0.0.1:8000/api/health>.


## Реализованные функции

- главная страница с быстрым поиском и переходами в разделы;
- каталог героев с поиском и фильтрами по атрибуту, роли и типу атаки;
- карточка героя со способностями, талантами и примерными предметами из гайдов;
- каталог предметов с категориями, ценой и описаниями;
- история патчей и привязанные изменения;
- список опубликованных гайдов и карточка гайда с предметами и комментариями;
- сравнение базовых параметров двух героев;
- форма создания гайда с сохранением черновика или передачей на модерацию в Supabase PostgreSQL;
- REST API на Node.js и автоматические тесты.

## GitHub

Чтобы опубликовать проект в собственном аккаунте, создай пустой репозиторий `DotaCodex`, затем открой терминал в этой папке и выполни:

```bash
git init
git add .
git commit -m "Initial Node.js DotaCodex MVP"
git branch -M main
git remote add origin https://github.com/<ВАШ_ЛОГИН>/DotaCodex.git
git push -u origin main
```

Замените `<ВАШ_ЛОГИН>` на свой логин. После отправки кода открой вкладку **Actions** и проверь выполнение workflow.

## Безопасность и ограничения

- URL и пароль подключения к Supabase хранятся только в локальном `.env` или GitHub Secret `SUPABASE_DATABASE_URL`; не добавляй их в Git и не помещай в браузерный код.
- API гайдов в этом MVP сохраняет записи от демонстрационного автора `RuneWriter`; перед публикацией в интернет нужен полноценный вход и проверка прав.
- База содержит вымышленные/учебные описания патчей. Перед игровым применением данные нужно заменить актуальными сведениями.
